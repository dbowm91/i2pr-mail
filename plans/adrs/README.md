# Architecture Decision Records

Use an ADR for durable decisions affecting ownership boundaries, public contracts, storage/recovery semantics, authentication/authorization, external standards/dependencies, or long-term non-goals.

Accepted ADRs are historical records. Supersede them with a new ADR rather than silently rewriting the decision.

Required fields: status, date, decision owners, related canonical sections, affected roadmaps, context, drivers, considered options, decision, consequences, compatibility/migration, security/reliability, verification, supersession.
